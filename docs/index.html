Why it works特徴

One layout. Three tools.1つのレイアウトで3ツール

Every profile shares the same key map — the only thing that changes is the theme colour. Your muscle memory transfers across tools. どのプロファイルでも同じ位置のキーは同じ意味。変わるのはテーマ色だけなので、指の記憶がそのまま他ツールでも使えます。

Unified layout統一レイアウト

Same key, same meaning on Claude Code, Codex, and Cursor. Tool differences (Return / a / ⌘⌫ …) are absorbed by a built-in translation table. You tell tools apart by theme colour: purple / teal / blue. Claude Code・Codex・Cursor で同じ位置のキーは同じ意味。ツール差（Return / a / ⌘⌫ など）は内蔵の翻訳テーブルが吸収。見分けはテーマ色（紫/ティール/青）のみ。

State-guarded keys誤爆防止ガード

Accept / Reject only fire while the lane is orange (Input) — Cursor also allows green (Done) for accepting all pending edits. Stop fires only on blue or orange. A guard-blocked press sends nothing: you get a warning sound and a red flash on the key. While a lane is orange, the Accept key itself blinks orange (Armed). Accept / Reject は橙（Input）のときだけ送出（Cursor のみ緑 Done でも有効＝変更の一括承認/棄却）。Stop は青/橙のときのみ。ガードに阻止された押下は何も送出されず、警告音＋キーの赤フラッシュで知らせます。橙の間は Accept キー自体がオレンジ点滅（Armed）します。

5 dynamic lane cards5枚の動的レーンカード

Each top-row key is a full-colour card: state label, elapsed time, session name, and — while orange — what awaits approval (e.g. Bash: git push). Thinking breathes, Input blinks, Done pops a white check; lanes light up left to right at startup. Press a lane to mark it read and focus the tool — Cursor jumps straight to that project's window via a cursor:// deep link. 上段5キーは全面1色のカード（状態色＋白抜き文字）。状態ラベル・経過時間・セッション名、橙のときは承認内容（例 Bash: git push）を表示。作業中は呼吸、承認待ちは点滅、完了直後は白チェックのポップ、起動時は左から順に点灯。押すと既読化＋フォーカスで、Cursor は cursor:// ディープリンクで該当プロジェクトのウィンドウへ直接ジャンプします。

Dials + Tool keyダイヤルと Tool キー

The left dial scrolls, the middle dial switches sessions/chats, and the right dial opens the autonomy menu (Effort / command menu / model). The Tool key on Page 3 cycles Claude ↔ Codex ↔ Cursor (Studio auto-restarts, ~9 s). 左ダイヤルはスクロール、中ダイヤルはセッション／チャット移動、右ダイヤルは自律軸メニュー（Effort / コマンドメニュー / モデル）。ツール切替は Page 3 の Tool キー（Studio が自動再起動・約9秒）。

Auto-focus, then send自動前面化→送出

Every key automatically brings the target app to the front, verifies it is frontmost, then sends. You never need to bring the app to the front yourself. どのキーも「自動で対象アプリを前面化→前面確認→送出」。先にアプリを前面化しておく必要はありません。

Local bridgeローカルブリッジ

A resident process on 127.0.0.1:17823 aggregates agent state; the plugin diff-updates tiles about every 150 ms. Claude Code hooks push approvals to /event, and /dashboard shows every tool's lanes live in a browser on the same Mac. If the bridge stops, Accept / Reject / Stop are withheld and all lanes show dark-gray OFFLINE (after 3 consecutive failed fetches; recovers automatically). 常駐プロセス（127.0.0.1:17823）が状態を集約し、プラグインが約150msで差分更新。Claude Code の hooks が /event に承認を通知し、/dashboard では全ツールのレーンを同一 Mac のブラウザでライブ表示。ブリッジ停止時は Accept / Reject / Stop を送出せず、全レーンが濃灰 OFFLINE 表示（3回連続の取得失敗で表示・自動復帰）。

Setupセットアップ

Install in one scriptスクリプト1本でインストール

One installer wires the bridge, the plugin, and three ready-made profiles: Vibe · Claude Code, Vibe · Cursor, and the official-style Codex_D200X. インストーラ1本で、ブリッジ・プラグイン・3つのプリセット（Vibe · Claude Code / Vibe · Cursor / Codex_D200X）を配線します。

Requirements必要なもの

  • Ulanzi D200X (USB connection)（USB 接続）
  • Ulanzi Studio 3.1+ (Apple Silicon)
  • macOS 12+
  • Target apps: Claude.app / ChatGPT.app (Codex) / Cursor.app対象アプリ: Claude.app / ChatGPT.app（Codex）/ Cursor.app
  • Node.js 20+
  • Python 3 + Pillow (icon generation)（アイコン生成）

Installインストール

terminal
# get the repo, then run the installer
git clone https://github.com/goonobu-dot/vibe-deck-for-d200x.git
cd vibe-deck-for-d200x
./scripts/install.sh
  1. Fully quit and relaunch Ulanzi Studio. Check that the three profiles appear: Vibe · Claude Code / Vibe · Cursor / Codex_D200X.Ulanzi Studio を完全終了→再起動。3つのプロファイル（Vibe · Claude Code / Vibe · Cursor / Codex_D200X）が表示されることを確認。
  2. Allow Ulanzi Studio in System Settings → Privacy & Security → Accessibility.システム設定 → プライバシーとセキュリティ → アクセシビリティで Ulanzi Studio を許可。
  3. Also allow Automation (System Events / control of each app) — the verb keys (Accept etc.) and profile switching use it.同じ項目でオートメーション（System Events / 各アプリの制御）も許可 — verb キー（Accept 等）とプロファイル切替が使用します。

First press: the first time you press a verb key, macOS may show an Automation permission dialog. You must approve it — until then, keys like Accept are silently not sent. 初回押下時: verb キーを初めて押すと macOS のオートメーション許可ダイアログが出ることがあります。必ず許可してください — 未許可の間は Accept 等のキーが送出されません。

Claude Code approval hooks (recommended)Claude Code 承認フック（推奨）

Register the bundled hook script in ~/.claude/settings.json — the Notification / Stop hooks report to the bridge's /event endpoint, so a lane turns orange the moment approval is requested. Replace the path with your own checkout. Hooks take effect from new sessions. 同梱のフックスクリプトを ~/.claude/settings.json の hooks に登録すると、Notification / Stop フックが bridge の /event へ通知し、承認要求の瞬間に確実にレーンが橙になります。パスは自分の環境に置き換えてください。hooks は新規セッションから有効です。

~/.claude/settings.json
{
  "hooks": {
    "Notification": [
      { "hooks": [ {
        "type": "command",
        "command": "\"/path/to/vibe-deck/scripts/claude-hooks/vibe-deck-event.sh\" needs_input"
      } ] }
    ],
    "Stop": [
      { "hooks": [ {
        "type": "command",
        "command": "\"/path/to/vibe-deck/scripts/claude-hooks/vibe-deck-event.sh\" done"
      } ] }
    ]
  }
}

FAQ & known limitsFAQ・既知の限界

Honest edges正直な限界も書いておきます

A few behaviours are by design, and a few are platform limits. Here is the full list. 仕様どおりの挙動と、プラットフォーム側の制約をすべて挙げます。

I press Accept and it beeps with a red flashAccept を押すと警告音が鳴りキーが赤くフラッシュする
Working as intended. The guard only lets Accept / Reject fire while the lane is orange (Cursor: also green), and Stop only on blue / orange. A blocked press sends nothing and answers with a warning sound plus a red flash on the pressed key. If ~/Library/Logs/vibe-deck-plugin.log shows guard blocked, it is behaving exactly as designed. 仕様どおりです。ガードにより Accept / Reject は橙のときだけ（Cursor は緑も）、Stop は青/橙のときだけ送出されます。阻止された押下は何も送出されず、警告音＋押したキーの赤フラッシュで知らせます。~/Library/Logs/vibe-deck-plugin.log に guard blocked とあれば仕様どおりです。
A lane turned dark green — what is that?レーンが深緑になった — これは何？
An unacknowledged completion. A lane that finished (green) more than 90 seconds ago turns dark green and is kept for up to 30 minutes so you don't miss it. Press the lane to mark it read — it returns to white. 未確認の完了です。完了（緑）から90秒を過ぎた未読レーンは深緑になり、見逃さないよう最大30分保持されます。レーンを押すと既読になり白へ戻ります。
Is there a way to see the lanes on screen too?レーンを画面でも見たい
Yes — open http://127.0.0.1:17823/dashboard in a browser on the same Mac. It shows every tool's lanes live. 同一 Mac のブラウザで http://127.0.0.1:17823/dashboard を開くと、全ツールのレーンをライブ表示できます。
The first key press shows a macOS dialog初回押下で macOS のダイアログが出る
That is the Automation (System Events) permission prompt. Approve it for Ulanzi Studio — until you do, verb keys like Accept are not sent at all. オートメーション（System Events）の許可ダイアログです。Ulanzi Studio を必ず許可してください。未許可の間は Accept などの verb キーが送出されません。
Tool switching takes about 9 secondsツール切替に約9秒かかる
Ulanzi Studio has no external API for profile switching (both WebSocket and UI scripting were verified not to work on real hardware). So the deck rewrites the config and auto-restarts Studio — about 9 seconds to come back, and the deck goes dark for a few seconds during the switch. Ulanzi Studio にはプロファイル切替の外部APIが存在しません（WS・UIスクリプト両方とも不可を実機検証済み）。そのため設定書換→Studio 自動再起動で実現しており、復帰まで約9秒かかります。切替中はデッキが数秒消灯します。
Codex keys don't do anythingCodex のキーが効かない
Codex verb keys assume the ChatGPT desktop app (ChatGPT.app). They are not designed to drive the browser version. Codex の操作キーは ChatGPT デスクトップアプリ（ChatGPT.app）前提です。ブラウザ版の操作は想定していません。
Claude's Voice key (⇪) is unreliableClaude の Voice（⇪）が不安定
Known limitation: Caps Lock is unreliable when sent from the deck due to macOS behaviour. Check Claude's voice-input setting, or use Caps Lock on the physical keyboard. 既知の制約です。macOS の仕様上、⇪ はデッキからの送出が不安定です。Claude 側の音声入力設定を確認するか、本体キーボードの ⇪ を使ってください。
Colours are slow or not updating色が遅い／変わらない
Try Refresh on Page 3 first. Then check the bridge: curl http://127.0.0.1:17823/health, restart Ulanzi Studio (reloads the plugin), and if you use the LaunchAgent: launchctl kickstart -k gui/$(id -u)/com.vibe.deck.bridge. On Cursor specifically, updates depend on transcript write timing. まず Page 3 の Refresh。次にブリッジ確認: curl http://127.0.0.1:17823/health → Studio 再起動（プラグイン再読込）→ LaunchAgent 利用時は launchctl kickstart -k gui/$(id -u)/com.vibe.deck.bridge。Cursor は transcript の書き出しタイミングに依存します。
What happens if the bridge stops?ブリッジが停止したら？
The deck fails safe: Accept / Reject / Stop are withheld entirely, and after 3 consecutive failed fetches every lane shows a dark-gray OFFLINE card. Other keys (Diff, New, Skills, System) keep working, and the lanes recover automatically once the bridge is reachable again. 安全側に倒れます。Accept / Reject / Stop は一切送出されず、取得が3回連続で失敗すると全レーンが濃灰の OFFLINE カード表示になります。他のキー（Diff / New / Skills / System）は動き続け、ブリッジが復旧すればレーンは自動で通常表示に戻ります。
Pages don't flipページが切り替わらない
Check that the two bottom physical buttons are assigned to Studio's standard Previous / Next page, and that the profile has 2+ pages. If not, re-run node scripts/wire-deck.mjs and restart Studio. 下段左右の物理ボタンが Studio 標準の Previous / Next page になっているか、対象プロファイルに Page が2つ以上あるかを確認。ダメなら node scripts/wire-deck.mjs を再実行して Studio を再起動してください。
