# Vibe Deck 操作ガイド — Cursor 編

対象プロファイル: **Vibe · Cursor**（テーマ色: ダークIDE＋青）
対象アプリ: Cursor.app

## 1. 画面の見かた

### 上段5キー = エージェントレーン（全ページ共通・動的カード）

Cursor のエージェントセッション最大5つが**全面1色のカード**（状態色＋白抜き文字）で並びます（transcript の書き出しタイミングに依存するため、反映は他ツールよりわずかに遅れることがあります）。カードには**状態ラベル・経過時間・名前（＝プロジェクトフォルダ名）**、橙のときは**承認内容**が表示されます。起動時は左から順に点灯します。

| 色 | 意味 | あなたがやること |
|----|------|------------------|
| 白 Idle | 待機中 | 指示を出す（New / Skills） |
| 青 Thinking | 作業中（呼吸アニメ。15分超で呼吸が約2倍速の長考アラート） | 待つ（止めたければ Stop） |
| 緑 Done | **編集完了直後（変更が保留中）**（白チェックがポップ） | Diff で確認 → Accept / Reject |
| 深緑 Done | **未確認の完了**（90秒後から最大30分保持） | レーンを押して既読に（白へ戻る） |
| 橙 Input | 承認・入力待ち（カード点滅・Accept キーもオレンジ点滅） | Accept / Reject |
| 赤 Error | エラー | レーンを押して画面確認 |
| 灰 Ready | 空きレーン | 押すと Cursor を前面化 |
| 濃灰 OFFLINE | bridge 不達（3回連続失敗で全レーン表示・自動復帰） | ブリッジを確認 |

**レーン押下 = 既読化＋フォーカス**。Cursor では `cursor://` ディープリンクにより**該当プロジェクトのウィンドウへ直接ジャンプ**します（パスの復号に失敗した場合はアプリ前面化にフォールバック）。3段目右端の細長い表示は本体の小窓ウィジェット（時計）で、キーではありません。**ページ移動は下段の物理ボタン左右**です。

## 2. Page 1 — CONTROL（このキーで実際に起きること）

| キー | 表示 | Cursor での実動作 |
|------|------|-------------------|
| 中段1 | Accept | Return 送信（承認/Run。**橙または緑で発火**。緑のときは「変更をすべて受け入れる」動きに相当） |
| 中段2 | Reject | ⌘⌫ 送信（**Reject all＝変更をすべて棄却**。橙または緑で発火） |
| 中段3 | Stop | ⌘⇧⌫ 送信（ターン中断。青/橙のときだけ発火） |
| 中段4 | Diff | ⌘E（Changes / Agent レイアウトを開く） |
| 中段5 | New | ⌘N（新規チャット） |
| 下段1 | Voice | ⌘⇧Space（音声入力） |
| 下段2 | Terminal | ⌃`（ターミナル開閉） |
| 下段3 | Mode | ⌘.（Agent / Ask モードメニュー） |

どのキーも押すと**自動で Cursor.app を前面化→前面確認→送出**します。

**Cursor 固有の注意**:
- **Cursor だけは緑（Done）でも Accept / Reject が有効**です。エージェントの編集完了後、Diff で確認して Accept（全部通す）か Reject（⌘⌫で全部戻す）を手元で選べます。
- **MCP 承認の既知問題**: 承認ダイアログのフォーカスがずれていると Return 単体で効かないことがあります（Cursor 公式の既知問題）。効かなかったら本体キーボードで Tab → もう一度デッキの Accept を押してください。
- Reject（⌘⌫）は「Reject all」です。一部だけ棄却したい場合は Diff を開いて画面上で個別に操作してください。

## 3. Page 2 — SKILLS（定型プロンプト8）

押すとチャット入力欄にプロンプト冒頭が入力されます（**送信はされません**。続きを書いて Return）。

中段: Plan / Implement / Review / Fix / Test
下段: Explain / Commit / Summary

コードを選択してから Skills を押すと、選択範囲を文脈にした指示が出しやすくなります（選択を明示的に渡すなら Page 3 の Context）。

## 4. Page 3 — SYSTEM

共通行（中段）: Tool（押すたびツール切替）/ Refresh（状態色の再取得）/ Settings（⌘,）/ Help（⇧⌘P コマンドパレット）/ **Model（⌘/ モデル切替）**

**Cursor 固有ゾーン（下段3キー）**:

| キー | 動作 |
|------|------|
| Composer | ⌘I（Composer / エージェントパネル） |
| Context | ⇧⌘L（選択中のコードをチャットの文脈に追加） |
| Inline | ⌘K（インライン編集＝カーソル位置・選択範囲の局所修正） |

## 4.5 Page 4 — COMMANDS（自走コマンド）

中段の5キーは全ツール共通の「自走プロンプト」です。押すと入力欄に文が入ります（**送信はされません**。Goal は続きにゴールを書いて Return、他は必要なら補足してから Return）。

| キー | 動作 |
|------|------|
| Goal | 「ゴール: 次の状態になるまで自走で完了させてください → 」を入力（続きにゴール条件を書く） |
| Continue | 「続きを完了まで進めてください。途中で止まらず、詰まったら状況を報告してください。」を入力 |
| FixAll | 「残っているエラー・警告・テスト失敗をすべて修正してください。」を入力 |
| TestAll | 「テストを追加・実行し、全部通るまで修正を繰り返してください。」を入力 |
| Ship | 「変更をセルフレビューして、コミットメッセージを付けてコミットまで仕上げてください。」を入力 |

**Cursor 固有ゾーン（下段3キー）**:

| キー | 動作 |
|------|------|
| NextDiff | ⌥↓（次の差分ハンクへ移動） |
| PrevDiff | ⌥↑（前の差分ハンクへ移動） |
| Queue | ⌃Return（指示をキューに積む＝現ターンを止めずに次の指示を予約） |

## 5. ダイヤル（全ページ共通）

| ダイヤル | 回転 | 押し込み |
|----------|------|----------|
| 左 | スクロール（左=下 / 右=上） | — |
| 中 | チャット移動（⌘[ 前へ / ⌘] 次へ） | — |
| 右 | ⌘/（モデルメニューを開く） | Mode（⌘.） |

**ツール切替は Page 3 の Tool キー**です。押すたび Claude→Codex→Cursor と巡回し、Studio が自動再起動して切り替わります（約9秒・数秒消灯は正常）。

## 6. おすすめワークフロー

1. エディタでコードを選択 → Context（⇧⌘L）→ 指示。小さな修正なら Inline（⌘K）
2. 青 → 放置
3. **橙 → Accept / Reject**（効かなければ Tab → Accept）
4. **緑 → Diff で差分確認 → Accept（全部通す）or Reject（全部戻す）**
5. 承認が多すぎる → Cursor 側の Auto-review / allowlist 設定を緩めるのが本筋

## 7. 困ったとき

- **キーが効かない（初回）**: システム設定 → プライバシーとセキュリティ → オートメーション で Ulanzi Studio → System Events を許可
- **Accept が効かない（橙）**: MCP 承認のフォーカス問題の可能性。Tab → Accept
- **Accept を押したら警告音が鳴ってキーが赤くフラッシュした（白/青）**: ガードが送出を止め、音とフラッシュで知らせています（正常）。`~/Library/Logs/vibe-deck-plugin.log` に `guard blocked` とあれば仕様どおり
- **色の反映が遅い**: Cursor の transcript 書き出し待ちです。Page 3 の Refresh で再取得できます
