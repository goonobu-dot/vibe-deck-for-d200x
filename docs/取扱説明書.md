# Vibe Deck for D200X 取扱説明書

OpenAI Codex Micro に近い「エージェントの色監視＋手元操作」を、Ulanzi D200X 上で Claude Code / Codex / Cursor 向けに実現するセットです。

## 1. 同梱物

| 項目 | 内容 |
|------|------|
| Bridge | エージェント状態を集約する常駐プロセス（高速キャッシュ＋監視） |
| Plugin | レーンカード描画・色更新・プロファイル巡回・ページ切替 |
| Presets | `Vibe · Claude Code` / `Vibe · Cursor` / 公式 `Codex_D200X` |
| 本説明書 | セットアップと使い方 |
| クイックリファレンス | キー配置の一覧 |

## 2. 必要なもの

- Ulanzi D200X（USB 接続）
- Ulanzi Studio 3.1+（Apple Silicon）
- macOS 12+
- 対象アプリ: Claude.app / ChatGPT.app（Codex）/ Cursor.app
- Node.js 20+
- Python 3 + Pillow（アイコン生成）

## 3. セットアップ

```bash
cd /path/to/skill/vibe-deck
./scripts/install.sh
```

その後:

1. **Ulanzi Studio を完全終了→再起動**
2. プロファイルに `Vibe · Claude Code` / `Vibe · Cursor` / `Codex_D200X` があること
3. **システム設定 → プライバシーとセキュリティ → アクセシビリティ** で Ulanzi Studio を許可
4. 同じ項目で **オートメーション（System Events / 各アプリの制御）** も許可 — Accept 等の verb キーとプロファイル切替が使用します。初回押下時に許可ダイアログが出たら必ず許可してください（未許可だとキーが送出されません）

ナビだけ再配線する場合:

```bash
python3 scripts/generate-icons.py
python3 scripts/generate-tool-themes.py
node scripts/wire-deck.mjs
# その後 Studio 再起動
```

## 4. 本体操作（重要）— 統一レイアウト「Vibe Deck OS」

**3ツール共通**: どのプロファイルでも同じ位置のキーは同じ意味。ツール差（Enter / `a` / ⌘⌫ など）はプラグイン内の翻訳テーブルが吸収し、ツールの見分けは背景テーマ色のみ。

### 上段 = エージェントレーン（全ページ共通・動的カード）

`0_0`〜`4_0` は現ツールの並列セッション slot 1〜5 の**全面1色カード**（状態色＋白抜き文字）。カードには**状態ラベル・経過時間・セッション名**、橙のときはさらに**承認内容**（例 `Bash: git push`）が表示される。起動時は左から順に点灯し、ページを切り替えても常に表示される。

カードの名前の出どころ:

| ツール | カードに出る名前 |
|--------|------------------|
| Claude Code | セッションタイトル |
| Codex | スレッド名（無名のスレッドは開始日時 `7/31 10:19`。スレッドに名前を付けると表示される） |
| Cursor | プロジェクトフォルダ名 |

**レーン押下 = 既読化＋フォーカス**。完了レーン（緑/深緑）は押すと既読=白に戻る。Cursor は `cursor://` ディープリンクで**該当プロジェクトのウィンドウへ直接ジャンプ**する（パス復号に失敗した場合と Claude / Codex はアプリ前面化）。

### AI プロファイルのページ構成

| ページ | 中段 | 下段（3キー＋右端は小窓バー） |
|--------|------|------|
| 1 Control | Accept / Reject / Stop / Diff / New | Voice / Terminal / Mode |
| 2 Skills | Plan / Implement / Review / Fix / Test | Explain / Commit / Summary |
| 3 System | Tool（ツール切替） / Refresh / Settings / Help / Model | ツール固有ゾーン（ツールで変わる行） |
| 4 Commands | Goal / Continue / FixAll / TestAll / Ship（自走プロンプト。送信はしない） | ツール固有ゾーン（Claude: Compact・Session・PickEl / Codex: Goal・History・Panel / Cursor: NextDiff・PrevDiff・Queue） |

下段右端の細長い表示は本体の小窓ウィジェット（時計）で、キーは配置していません。ページ移動は下段の物理ボタン左右で行います。

### 安全機構（誤爆防止）

- Accept / Reject は橙（Input）以外では送出されない（Cursor のみ緑 Done でも有効）
- Stop は青（Thinking）/橙のときのみ有効
- **ガードフィードバック**: ガードに阻止された押下は送出されず、警告音＋押したキーの赤フラッシュで知らせる
- **Armed 表示**: 橙のレーンがある間は Accept キー自体がオレンジ点滅し、押すべきキーが一目でわかる
- 各キーは「自動で対象アプリを前面化→前面確認→送出」。先にアプリを前面化しておく必要はない
- ブリッジ停止時は Accept / Reject / Stop を送出しない（安全側）。レーンは濃灰 OFFLINE 表示になる

### ダイヤル（全ページ共通・Studio標準ホットキー方式）

- 左（`2_3`）: 回転=スクロール（下/上）
- 中（`3_3`）: 回転=セッション/チャット移動（ツール別ショートカット）/ Codex のみ押し込み=⌘G
- 右（`4_3`）: **メニュー選択ジョグ** — 回転=↑/↓（開いているメニュー内を移動）/ 押し込み=Return（確定）
- **ツール切替は Page 3 の Tool キー**（押すたび Claude→Codex→Cursor と巡回。Studio が自動再起動して切替・約9秒）

※Ulanzi Studio はプラグイン独自アクションへのダイヤルイベント配信をサポートしないため（実機検証済み）、ダイヤルは標準ホットキーのみで構成しています。

### 下段の左右物理ボタン = ページ切替（Studio 標準）

- 左（`0_3`）: 前のページ（`page.prev`）
- 右（`1_3`）: 次のページ（`page.next`）

## 5. 状態色（レーンカードの色言語）

ステータス色は全ツール共通です。レーンは全面が状態色のカードになり、文字は白抜き（Idle のみ濃色文字）で表示されます。

| 色 | 状態 | ラベル | 意味・動き |
|----|------|--------|------------|
| 白 | idle | IDLE | 待機中 |
| 青 | thinking | THINK | 作業中。呼吸アニメ（GIF）。**15分を超えると呼吸が約2倍速になる長考アラート** |
| 緑 | done | DONE | ターン完了直後。白いチェックがポップ表示される |
| 深緑 | done_old | DONE | **未確認の完了**。完了から90秒を過ぎた未読レーン（最大30分保持）。レーン押下で既読=白へ |
| 橙 | needs_input | INPUT | 承認・入力待ち。カードが点滅し、承認内容（例 `Bash: git push`）を表示 |
| 赤 | error | ERROR | エラー |
| 灰 | empty | READY | 未使用レーン（押すとそのツールを前面化） |
| 濃灰 | offline | OFFLINE | **bridge 不達**。取得が3回連続で失敗すると全レーンに表示され、復旧すると自動で通常表示に戻る |

Studio のタイトル文字はオフにし、ラベルはカード内の英語のみ表示します（日英の重なり防止）。

### ツール別デザイン

コマンドキーはツールごとに見た目が違います。

| プロファイル | トーン |
|--------------|--------|
| Codex_D200X | 黒＋ティール（チャット） |
| Vibe · Cursor | ダーク IDE＋青（キャレット） |
| Vibe · Claude Code | 深紫＋オレンジ（スパーク） |

## 6. 色のレスポンス

プラグインは約 150ms 間隔で差分更新します。ブリッジは Cursor の transcript を監視し、短いキャッシュで応答します。  
体感の上限は Cursor 側が transcript を書き出すタイミングです。

## 7. ブリッジ

- URL: `http://127.0.0.1:17823`
- `GET /health`
- `GET /status?tool=codex|claude|cursor`
- `GET /status?tool=cursor&fresh=1` … キャッシュ無視
- `GET|POST /event?tool=claude&state=needs_input|done&session=<id>` … hooks からの状態通知（下記）
- `GET /dashboard` … **Web ダッシュボード**。同一 Mac 内のブラウザで `http://127.0.0.1:17823/dashboard` を開くと、全ツールのレーンをライブ表示
- Claude 状態は `~/.claude/projects/**/*.jsonl`（デスクトップ／CLI 共通）を監視。`claude agents --json` には依存しない

### 承認フロー（Claude Code hooks 連携）

Claude Code の **Notification / Stop フック**が bridge の `/event` へ通知することで、承認要求の瞬間に確実にレーンが橙になります（transcript 推測より確実）。橙の間は Accept キーがオレンジ点滅（Armed）します。

設定方法: `~/.claude/settings.json` の `hooks` に `scripts/claude-hooks/vibe-deck-event.sh` を登録します（パスは自分の環境に合わせて置き換え）。

```json
{
  "hooks": {
    "Notification": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "\"/path/to/vibe-deck/scripts/claude-hooks/vibe-deck-event.sh\" needs_input"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "\"/path/to/vibe-deck/scripts/claude-hooks/vibe-deck-event.sh\" done"
          }
        ]
      }
    ]
  }
}
```

hooks は**新規セッションから有効**です（設定後に開始したセッションから反映されます）。

## 8. トラブルシュート

**色が遅い／変わらない**

1. `curl http://127.0.0.1:17823/health`
2. Studio 再起動（プラグイン再読込）
3. `launchctl kickstart -k gui/$(id -u)/com.vibe.deck.bridge`（LaunchAgent 利用時）

**ページが切り替わらない**

1. 下段左右が Studio 標準の Previous / Next page になっているか
2. 対象プロファイルに Page が 2 つ以上あるか
3. `node scripts/wire-deck.mjs` 再実行 → Studio 再起動

## 9. アンインストール

```bash
launchctl unload ~/Library/LaunchAgents/com.vibe.deck.bridge.plist 2>/dev/null || true
rm -f ~/Library/LaunchAgents/com.vibe.deck.bridge.plist
rm -rf ~/Library/Application\ Support/Ulanzi/UlanziDeck/Plugins/com.vibe.deck.status.ulanziPlugin
pkill -f vibe-deck/bridge/dist/index.js || true
```
